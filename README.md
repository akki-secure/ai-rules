Claude Code / Gemini などのAIコーディングエージェントに開発を任せる際に、
共通して守らせたいルールをまとめたテンプレートリポジトリです。

詳細なテンプレート本文は [AI_AGENT_RULES_TEMPLATE.md](./AI_AGENT_RULES_TEMPLATE.md) を参照してください。
`{ }` で囲まれたプレースホルダーを自分のプロジェクトに合わせて書き換えて使用します。

## 📋 ルール項目の目次

1. 要件定義書の作成(ask)→ **法律上禁止・届け出が必要な機能は実装せずユーザーに通知** → ブラウザで動く静的モックプロトタイプをheadfulモードで確認 → 要件定義書専用mdファイルの作成 / **初めて使う言語はコードにコメントを書かずチャットで説明**
2. 開発フロー(Plan Mode): Auto禁止・Manual承認で進める / コメント少なめでバックエンド→フロントエンド(**中央モーダルは「全画面コンテナ→中央揃えラッパー→モーダル本体」の3層**)→ガードレール(**破壊的操作は原則AIが実行せず、必要時はユーザーの明示的承認+バックアップ後のみ**)+ ログ設計 → 自動テスト → パフォーマンステスト(手動・別枠) / 機能ごとにheadfulモードで確認 / **コードの質問ではAIが対象ファイルを開いて確認**
3. レビュー・指摘時は該当箇所を原文のまま引用し、番号・数字・固有名詞は原文と照合してから指摘、確信がない場合は断定しない、ユーザーからの指摘にもすぐ同意せず原文確認してから返答
4. 不明な用語があれば必ずユーザーに質問する
5. README.mdとは別のMarkdownファイルに保存する
6. 動作確認前の品質チェック(静的解析、未使用ファイル・フォルダなどリポジトリ全体の棚卸しを含む、**棚卸しチェックリスト**: lint/型/テスト/ビルド・未使用の依存/ファイル/export・シークレットスキャン・`pnpm audit`・禁止SQL/DB権限/LICENSE/READMEの必須要素)、SQLデータ保護(DELETE/DROP/TRUNCATEは2章の破壊的操作ルールに従う)、**DBはrootを使わずアプリ専用ユーザーを作成(最小権限の原則)**、自動テスト実行(エラーで止まらないよう別処理で継続 / **N+1問題の対策** / 30分以上かかる場合はフリーズを疑い確認)、AIによる動作確認は必ずheadful(ヘッドフル)モードで行う
7. mainブランチはユーザーが作成、AIは別ブランチを作成してpush(mainへの直接pushは禁止)、**マージ済みブランチが削除されているか確認**、最初のコミット前に`.gitignore`とLICENSEを整備、**(任意)GitHub ActionsでPR作成・push時にClaude Codeが自動レビューしコメント投稿(導入前に必ずユーザーの承諾、使用モデルは`/model`で確認、認証情報はGitHub Secretsにユーザー自身が登録、権限は最小限、月額の費用上限を設定、マージ判断は人間)**
8. 完了時の感謝の一言で締めくくる
9. 次の段階に進む前にClaude Codeのセッションを開き直す
10. skillsと`.claude/commands/`フォルダを作成し、`/コマンド`で操作(パフォーマンステスト用の`/performance-test`など)
11. 全体の品質チェックを複数回実施、うち1回はリポジトリ構成全体を俯瞰(SQLはXML管理、画像は見るまで断定しない)、機密情報は`.env`管理+`.env.example`コミット+**gitleaksによるシークレットスキャン(作業ツリー・git履歴の両方、`--redact`付き、PR作成前、`.gitleaks.toml`で除外設定、ダミー値は`test-`始まりのみallowlist、検出時は追跡確認→本物ならローテーション)**、**RCE等の深刻な脆弱性が確認されたら速やかにバージョンアップ対応**
12. 最後に自動テストを再実行し、**テストカバレッジで網羅できているか確認**、**使われていないテストは削除(有効なテストはリポジトリに残し、配布物・本番ビルドからは除外)**
13. README.mdに遷移図・モック・ER図・API仕様書を必ず追記し、機能追加のたびに更新(**デモ用のユーザー名・メールアドレス・パスワードの記載は禁止**)
14. 作ったプロジェクトについてAIからユーザーへ質問してもらう
15. デプロイはユーザー確認後、Terraform + AWS等で実行
16. リソース削除前にデータ・ログをバックアップし、確認後に`terraform destroy`

## 🚀 使い方

1. このリポジトリをテンプレートとして新しいプロジェクトにコピーする、または `AI_AGENT_RULES_TEMPLATE.md` の内容をプロジェクトのCLAUDE.md等に転記する。
2. プレースホルダー(`{アプリ名}` など)を実際の値に置き換える。
3. AIエージェントとの作業開始時に、このルールを読み込ませてから進める。
